# Контракты LLM

Это начальная спецификация. Финальные prompts будут уточнены после подготовки компактного профиля кандидата и тестовой выборки вакансий.

## Общие правила

- Использовать только факты из переданного профиля, резюме и проектных материалов.
- Не превращать гипотезы, обучение и эксперименты в оплачиваемый или production-опыт.
- Не придумывать сроки, метрики, клиентов, технологии и результаты.
- При недостатке данных явно указывать неопределенность.
- Не выполнять поиск вакансий внутри LLM-вызова.
- Не выполнять действия на hh.ru.

## Оценка вакансии

Вход:

- структурированные данные вакансии;
- компактный профиль кандидата;
- доступные варианты резюме;
- правила оценки и стоп-факторы.

Выход должен быть валидным JSON без Markdown:

```json
{
  "score": 0,
  "decision": "reject",
  "recommended_resume": "",
  "matching_requirements": [],
  "missing_requirements": [],
  "risk_flags": [],
  "evidence": [],
  "summary": "",
  "cover_letter_recommended": false
}
```

Допустимые decision:

```text
reject
review
recommend
```

Начальные пороги, требующие калибровки:

- 0-59: reject;
- 60-74: review;
- 75-100: recommend.

## Сопроводительное письмо

Письмо создается только для вакансии, прошедшей установленный порог.

Требования:

- язык вакансии;
- примерно 600-1200 знаков, если контекст не требует другого;
- конкретная связь с требованиями вакансии;
- два или три подтвержденных совпадения;
- один релевантный проект, кейс или результат при наличии;
- отсутствие неподтвержденных утверждений;
- спокойный профессиональный стиль;
- отсутствие шаблонных преувеличений;
- plain keyboard-safe punctuation согласно AGENTS.md;
- без Markdown-разметки в финальном тексте.

Выход должен быть валидным JSON:

```json
{
  "cover_letter": "",
  "facts_used": [],
  "warnings": []
}
```

## Валидация

Code JS после каждого вызова должен:

1. Удалить возможное Markdown-ограждение.
2. Разобрать JSON.
3. Проверить обязательные поля.
4. Проверить диапазон score от 0 до 100.
5. Проверить допустимое значение decision.
6. Ограничить длину массивов и строк.
7. При ошибке выполнить не более одного исправляющего запроса.
8. При повторной ошибке сохранить статус error и уведомить пользователя.
